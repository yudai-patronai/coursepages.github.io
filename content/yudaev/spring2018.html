Задание 1

Дописать в уже известную игру с арифметическими драконами клиент-серверное взаимодействие. Исходный код можно найти здесь.(Файл CMakeLists.txt генерится интегрированными средами разработки, использующими кросс-платформенный компоновщик cmake вместо make - это для тех, кто работает под виндовс. Проще же всего скачть только папку src - там уже есть Makefile - и поступать дальше так же, как в прошлом семесте. пользуясь стандартным make - см, например, первую лабораторную третьего семестра) Клиент должен посылать серверу запрос на допуск до игры, сервер должен регистрировать клиента как активного в данный момент и отправлять ему подтверждение участия. Сервер посылает клиенту задания(в виде строк), клиент показывает их пользователю. считывает его ответы и отправляет их обратно серверу. Сервер обязан хранить во время выполнеения статусы всех подключенных клиентов и писать лог в специальный файл, где каждая строка ссответствует одному событию. Событием является получение любых данных от клиентов(подключение, отключение, правильный/неправильный ответ, выигрыш/проигрыш). Каждое событие фиксируется в файле loghh:mm;dd-mm-yy.txt(то есть три буквы log, затем по 2 цифры от часов и минут и от даты в формате день-месяц-год времени начала записи этого файла) в виде одной строки, где указывается точное время, затем id клиента и тип события. При завершении работы сервер должен закрыть файл лога.
Небольшой ликбез о клиент-серверном взаимодействии исокетах (для тех, кому интеерсно, использовать их необязательно, как уже сказано).

Каждый клиент характеризуется своим pid, так как этот номер у каждого процесса уникален. Передачу сообщений организовать через стандартную очередь IPC V. Кто сможет организовать связь через сокеты и сетевой протокол, например, UDP - получит бонусные баллы, поскольку на семинарах этого не было. Организация работы клиент-серверного взаимодействия описана, например, в учебнике Карпова-Конькова на стр 413. В случае остановки сервера - он должен разослать всем клиентам сигнал kill.(см стр 465-467)
